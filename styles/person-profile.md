# Person Profile 风格 — 人物画像笔记

## 定位

对一个人物的系统化认知笔记：目标是**读完后能充分了解这个人** —— 他是谁、经历了什么、主张什么、输出了什么、如何影响别人。适用于投资人、企业家、学者、博主、开源作者等任何"以输出立身"的人物。

结构对齐 media-summary 的四部骨架（背景/结论/正文/参考），不随意增删。


## 工作流（从原始数据到成稿）

### 步骤 1：准备 sources.json

- 知乎人物：先跑 `/zhihu-archive <主页链接>` 完成归档，再执行
  `python3 <zhihu-archive>/scripts/export_sources.py --raw <归档>/_raw`
- 其他平台：写对应的 export 脚本产出同格式 sources.json，或手工整理
- 没有结构化数据（如只有访谈/文章若干篇）时，可手工构造 items（附录可只含索引行）

### 步骤 2：agent 深读全部原始内容（结论≥1000 字的前提）

内容量大时（>50 条），**必须派多个并行 agent 穷尽精读**，不要只抽读高赞内容——
低赞内容常有独有干货。切分规则：每个 agent 约 80 条，按时间顺序切。

给 agent 的任务模板要点：
- 精读指定范围的全部文件，穷尽式提炼（不要只看高赞）
- 按 主题分组输出：方法论（保留具体数字参数）/ 具体案例 / 市场判断 / 人生观认知 / 自传性事实 / 金句（直接引用）
- 每条注明出处文件名
- 最后给出该阶段的主题特征观察

### 步骤 3：写正文（new → 四部结构）

```bash
cd ~/Documents/Notes/ai-notes && bash $SCRIPT new <workspace> "<person-english-slug>"
```

按本模板四部结构写入。写作要点：
- 标题：`人物调研：<人物名>（<身份关键词>）`
- 背景/叙述面向读者（此人是谁、为何值得关注），不写研究过程与工具链
- 结论 ≥1000 字、信息密度优先，基于 agent 纪要综合
- 引用用作品名+日期，不放附录编号
- 段落/列表/表格之间必须空行

### 步骤 4：生成附录并追加

```bash
python3 <ai-notes>/scripts/appendix.py --sources <sources.json> >> <笔记路径>
```

### 步骤 5：发布与验证

```bash
cd ~/Documents/Notes/ai-notes && bash $SCRIPT pub <笔记>   # 必须用 pub，重写文件会丢 access: pub
```

浏览器打开线上页面验证（举一反三清单）：
- [ ] TOC 干净：只有四部 + 3.x + 附录 A/B/C，无原文内容标题混入
- [ ] 附录链接全部可点击（知乎原帖可跳转）
- [ ] TODO checkbox 正常渲染
- [ ] 无转义 HTML 残留、无裸 `<a>`/`<br>` 可见文本
- [ ] 页面公开无密码提示
- [ ] 正文无附录编号残留（grep '\[[ABC]\d+\]'）

## 原则

1. **客观优先**：事实与判断严格分离。判断须显式标注`【判断】`并附出处作品名；无证据的判断不写。**正文不插入附录编号标记**（如 [A122]，影响阅读），溯源靠附录索引和自然提到的作品名/日期
2. **输出导向**：人物靠输出（作品/言论/行动）被理解，不靠标签堆砌，每个论断落到具体作品
3. **面向读者叙事**：笔记是给读者介绍这个人的，背景与叙述从"此人为何值得关注"切入；研究过程、工具链（归档 skill、爬虫、agent）等内部细节一律不进正文和参考
4. **平台无关**：内容类型用通用分类（长文/短内容/即时动态/音视频/著作/代码），平台名称只出现在信息行和附录，保证模板跨信息源复用
5. **原文不改写**：引用原话用引用块；推测须标注 `[原文: xxx → 推测: yyy]`
6. **附录全量**：参考区附录收录**全部原始数据**（每条原文+链接，按内容类型结构化整理），由脚本自动生成，`<details>` 折叠避免淹没正文
7. **可横向对比**：字段结构固定，多个同领域人物笔记可逐节对比

## 附录自动化（sources.json 统一格式）

附录由 `scripts/appendix.py`（本 skill）生成，输入为**平台无关的 sources.json**。
信息源 skill（如 zhihu-archive）负责把自己的原始数据导出成该格式；手工整理其他来源时也按此格式。

```json
{
  "person": {"name": "...", "source": "zhihu", "profile_url": "..."},
  "category_order": ["短内容", "长文", "即时动态"],
  "items": [
    {"category": "短内容",      // 通用分类，须出现在 category_order
     "kind": "answer",         // 来源内部类型，仅备注
     "date": "2026-06-03",     // YYYY-MM-DD
     "title": "...",
     "url": "...",             // 原文链接
     "metrics": {"赞": 376, "藏": 29568, "评": 428},  // 任意指标，列自动合并
     "content_md": "..."}      // 可选，仅代表作携带，供全文收录
  ]
}
```

```bash
# 信息源侧导出（以 zhihu-archive 为例；默认全量携带正文）
python3 <zhihu-archive>/scripts/export_sources.py --raw <归档>/_raw
# ai-notes 侧生成附录块（stdout，追加到笔记「四、参考」末尾）
python3 <ai-notes>/scripts/appendix.py --sources <sources.json>
```

编号规则：各分类内按日期正序编号（A1、A2…），编号稳定便于定位；正文不插编号标记，溯源用索引表的日期/标题检索。

## 写作规则

- 正文中文，专有名词保留原文
- 事实性结论附出处作品名/日期（不放编号标记）；缺失信息写"未公开/待验证"，不脑补
- 数据给具体数字和统计时点，不写"很多/大量"
- 主观评价克制：只保留有证据支撑的判断，且显式标注`【判断】`
- 文件命名：`YYYY-MM-DD-<person-english-slug>.md`
- **markdown 空行**：段落、列表、表格之间必须空一行（如 `**TODO**：` 后直接跟 `- [ ]` 列表会被吸收进段落，不渲染）
- 标题/表格单元格里不要放裸 HTML 标签（会被转义成可见文本）；链接一律用 `[文字](url)` 语法
- 敏感人物：只收录公开信息

## 节的取舍

四部结构固定不增删。三、正文各子节信息不足时精简内容，但**保留节标题**（保证横向对比结构一致）；3.7 无争议可写"未见公开争议"。

## 与其他风格的区别

| | default | research | media-summary | person-profile |
|---|---|---|---|---|
| 对象 | 技术/事件 | 技术深度问题 | 视频/音频 | 人物 |
| 骨架 | 背景/结论/内容/Action | 背景/结论/内容/FAQ | 背景/结论/正文/参考 | 背景/结论/正文/参考 |
| 证据 | 命令/配置 | 实验/数据 | 转写原文 | 作品/言行（附录全量原文） |
| 独有 | Action | 复现/FAQ | 嵌入播放器/完整转写 | 附录全量原文（编号可引用） |
