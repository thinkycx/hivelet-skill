# Research 风格 — 深度研究报告

## 原则

1. 问题驱动：一篇文章围绕一个明确问题展开深度研究
2. 结论先行：核心发现在第二部分加粗一句话
3. 概念自包含：假设读者是 3 个月后的自己，基础概念必须铺到位
4. 可操作：读完能 copy-paste 命令/配置直接上手
5. 边界清晰：FAQ 收尾处理所有"那如果..."类延伸问题

## 与 default 风格的区别

| | default | research |
|---|---|---|
| 篇幅 | 精简，核心观点 + Action | 长文，概念铺垫 + 深度分析 |
| 基础概念 | 不展开 | 必须独立章节，图文并茂 |
| 图表 | 可选 | 必须（ASCII 架构图、时序图、对比表） |
| 可复现性 | 给结论即可 | 给完整命令/配置/工具/成本 |
| FAQ | 无 | 必须，处理边界和延伸问题 |
| 目标读者 | 当下的自己 | 3 个月后已忘记上下文的自己 |

## 写作规则

- 正文中文，代码/命令/专有名词用英文
- 段落短小（不超过 5 行）
- 结构化对比必须用表格，不用纯文字罗列
- ASCII 图用于架构和数据流（不依赖外部图片工具）
- 代码块标注语言，配置文件加行内注释
- 时序/流程用带时间轴的格式或分阶段框图
- 不用套话（"本文将介绍..."、"众所周知..."）
- 不出现内部公司名、产品名、SSID 等敏感信息
- 文件命名：`YYYY-MM-DD-<english-slug>.md`

## 子章节取舍

3.1-3.3 为必选。3.4-3.7 按实际内容取舍：
- 攻击研究类：3.4(防御) + 3.5(复现) + 3.6(工具) 必选
- 架构设计类：3.4(tradeoff) + 3.5(落地计划) 必选
- 故障分析类：3.4(影响) + 3.5(修复验证) 必选
- 技术调研类：3.4(对比) + 3.7(横向) 必选

## 图片规范

- 优先用 ASCII 图（无外部依赖）
- 需要截图时存放在 workspace 内的 `assets/` 目录
- 命名：`YYYY-MM-DD-<描述性名称>.<ext>`
- 引用：`![描述](assets/YYYY-MM-DD-name.png)`
